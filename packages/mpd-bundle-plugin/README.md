# mpd-bundle-plugin

**English** | [中文](./README.zh-CN.md)

The `@mpd-dsh/mpd` bundle's own main plugin and web-client surface. Two jobs:

1. **Web-compat main** — the bundle package's `main` / `exports["."]` points here. It
   is a no-op plugin (`apply() {}`) whose name is `@mpd-dsh/mpd`. The bundle patch's
   `mpd-web-compat` self-row (`name: '@mpd-dsh/mpd'`) loads it, which makes the loader
   entry named **exactly** `@mpd-dsh/mpd` — the entry that client-modules requires to
   build a boot-graph client row for the bundle (without it no client surface loads).
2. **Combined web client** — `client.js` (generated by `scripts/build-mpd-client.ts`)
   is served as the bundle's `./client` export:
   - the retired agent-teams `lib/client.js` verbatim (it self-registers
     `@nanmicoder/dsh-agent-teams`). **No mpd client source requires it any more** (0.1.7):
     the official `@deepseek-ai/dsh-experimental-client-ui-agent-team` client, mounted by
     this bundle's `mpd-ui-agent-team` row, owns the roster and task-board UI, and the
     retired client's bytes remain in the combined file only because
     `scripts/build-mpd-client.ts` still embeds them (a follow-up for that script),
   - a `@mpd-dsh/team-page` registration whose factory is `src/team-page.ts`: the bundle's
     **team WATCHDOG page**, contributed as a **DSH-better-sidebar** tab (id
     `mpd-agent-teams` — kept, because the sidebar throws on a duplicate id and the host
     keys restored tabs on it — order 85, `single: true`, unread-incident badge, no
     auto-open). It renders the hold per team, the newest WARN/ESCALATE banner and the
     unread-incident replay from this bundle's OWN routes
     (`/plugins/mpd-team-watchdog/{state,ack}`, served by `src/watchdog-web.ts`) and
     acknowledges one incident with a POST. It does NOT duplicate the official roster
     panel, reads no team record, and without the sidebar it logs one warning and
     registers nothing,
   - a `@mpd-dsh/mpd` registration whose factory contributes the workmate library as its
     own **DSH-better-sidebar** tab (`mpd-workmate`, order 90, `single: true`), which
     reads and creates workmates via `GET /plugins/mpd-workmate/{list,roster,get}` +
     `POST /plugins/mpd-workmate/init`, and
     renames/deletes them via `POST /plugins/mpd-workmate/{rename,delete}` — branching on
     the reason-coded refusals (`invalid-name` / `confirm-required` / `unknown` /
     `collision` / `in-use` with the blocking team list), with an explicit two-step delete
     (confirmation → archive, or a typed-name purge) and zh/en strings. Bases are addressed by **functional NAME only**: the tab renders names, never a roster id (the ids are internal and the workmate routes no longer carry them). It
     also registers the vestigial null `conversation.chat.commandview` row (kept so a host
     that still routes a `/agent-teams` result through that slot hides it). There is NO
     floating fallback for either page:
     `scripts/build-mpd-client.ts` fails the build if any mpd client source registers
     `agent-teams-activity`, `conversation.chat.node`, `shell.overlay` or
     `sidebar.footer.action`.

**The team tab refreshes on a PUSH, and still polls.** The shared team view
(`src/team-view.ts`, the one body both sidebar hosts render) reads
`/plugins/mpd-team/{state,plan,task}` on its own `pollMs` interval (2000 ms) **and** subscribes to
`/plugins/mpd-team/events` — the Server-Sent-Events route `mpd-team-core-plugin` serves — through an
`EventSource` opened per MOUNT, for the session the panel is showing (the same `?sessionId=` the state
read carries). Every `data:` frame runs the SAME `tick` the interval runs, so a pushed and a polled
frame can never disagree. The interval stays as the **fallback**: a host without `EventSource`
(neither `node` nor `bun` defines the global, so the offline harness takes this path), a proxy that
cuts the stream, or a composition whose `eventsPath` is absent behaves exactly as it did before. The
stream is closed when the panel unmounts or the seat's session changes, and reconnecting after a
transport error is `EventSource`'s own retry (the route sends `retry: 1000`) — there is no reconnect
loop of ours. Because both hosts render this one component and the effect is per mount, two mounted
panels hold two streams.

**TUI counterpart.** The settings card this client registers is the browser half of the same
`mpd-config` ENTRY document the TUI edition renders as its `/settings` section
(`packages/mpd-tui-plugin/src/settings.ts`; the card mounts through `configForms.get(CONFIG_ENTRY)`,
`CONFIG_ENTRY = "mpd-config"` — the legacy `mpd` namespace is retired): labels, hints and zh
descriptions are mirrored
between the two front doors, a test asserts the two lists stay identical, and both state the same
bridge disclosure — a save from this card is persisted by the HOST as the `mpd-config` ENTRY document
and writes NO workspace `<workspace>/.mpd/mpd.jsonc` (the only writer of that file is the RETIRED
legacy `mpd`-namespace write-back, dormant on the pinned harness, while a hand edit of the file is
still read on every resolution), and the disclosure is SCOPED per knob instead of promising a blanket
restart: the model routes, the team-gate knobs, the `team.stateDir` reader and the two guards act in
the RUNNING process, while `hashline.*`, `commentChecker.*`, `autoproject.*`, `memory.*`, `boulder.dir` and
`goal.*` are captured at `apply()` and need the next `dsh` boot — and `watchdog.*` is NEITHER half: its
own row reads `settingsReader("mpd")` (refused here) and parses `<workspace>/.mpd/mpd.jsonc` itself, so
a hand edit of that file is live while a form save never reaches those knobs (`docs/user-guide.md` §9.1
is the per-knob authority; the same declaration in `settings-schema.ts` and in `settings-card.ts`). The browser
reaches the bridge only through the
public settings seam; the PERSISTENCE belongs to the host and the entry-document re-read to
`packages/mpd-config-plugin` (the legacy write-back lives there too, dormant). Rebuild the
combined client (`node scripts/build-mpd-client.ts`) after touching either half.

**The Web card's per-agent route rows.** The card mirrors the ONE knob declaration of
`packages/mpd-config-plugin` (the original 13 knobs, one three-leaf row per roster agent —
`agentRoutes.<Agent>.{provider,model,reasoningEffort}` — and the TUI surface's own knob) and
renders each agent's row as a **dependent, selection-only picker**: a model control whose options are
the catalog's provider/model pairs (provider shown as a group) and an effort control whose
options are the SELECTED model's own efforts, re-derived when the model changes. The catalog is
reached through GUARDED probes of `ctx.get("sessions")` + `ctx.get("modelDirectories")` — the
existing `team-page.ts` pattern, never a declared inject — and when a probe is absent, no session
is bound, or `directoryFor` throws, the card falls back to the DECLARED option lists and the
section still renders. Nothing about a leaf is settable only by typing. The see-before-you-edit block shows each agent's STATE and renders
`<unconfigured>` (naming the leaves it still needs) when the workspace configured none — there is no
default floor to invent a route — while an INVALID entry (a leaf present but malformed, e.g. a
non-string, or an entry that is not an object) renders its OWN sentence in both languages instead of
`<unconfigured>`: `EffectiveRoute.problem` names the offending leaf (`agentRoutes.<Agent>.leaf is not a
string`, or `agentRoutes.<Agent> is not an object`), and the `missing` check TRIMS every leaf, so a
whitespace-only leaf counts as MISSING rather than as configured — a malformed entry must never read as
absent. The legacy `teamModels` block is never rendered: there is no persisted slot, the four groups
are only the `/mpd-model` bulk-edit shortcut, and a leftover block in an old file is IGNORED and never
rewritten. A browser module cannot
import the TS declaration, so the card mirrors it and a test pins the declared metadata (path,
label, zh, kind, declared options, human sentences) element-wise. Each row LEADS with its
group heading and its own human sentence, and a group heading with a one-line impact sits above each
agent's three leaves. Both doors name the
dotted `mpd.jsonc` key through ONE helper — the hint is `<human sentence> (mpd.jsonc <key>)`, and a
knob with no human sentence keeps the pointer alone (`knobHint` in the TUI, `hintOf` on the card) —
while the bridge disclosure and the not-lost clause are stated ONCE per SECTION, never per row: the
TUI carries `SECTION_NOTICE` in the section's own description, and the card renders its disclosure
block once at the top (`data-mpd-disclosure`). **Both halves are rendered, not just the promising
one**: the LIVE half (the knobs whose behaviour a save changes in the running process) AND the
mount-captured exception (the knobs that need the next `dsh` boot) — the card's block carries the
scoped statement, and its copy in `settings-card.ts` stays byte-identical to the TUI's, so a reader
of either front door learns that the EFFECT is per knob (`docs/user-guide.md` §9.1).

## Nested groups: a subcell is a frame

The TEAM view paints a subcell as a frame instead of as one more task card. The host serves the box as a
node of the PARENT frame (`visual: "group"`) together with the model's `groups` list, and the drawing turns
each of those items into a `.mpd-dag-group` rectangle in a layer of its own — so the painted order is
`svg` edges, then the frames, then the task cards, and no `data-mpd-node` ever carries a group's id.

- **A box is its INTERIOR, laid out recursively.** Each frame's own items are placed by the same rules a
  flat drawing uses — columns by the served column, stacked in id order, a crossing band reserved above the
  boxes for the rank-skipping edges — and the box is then sized to that interior plus the frame's own
  padding, so the rectangle it publishes (`data-mpd-group="<id>,<left>,<top>,<width>,<height>"`) encloses
  the cards and the nested boxes it holds. Nesting repeats: a subcell inside a subcell gets its own frame,
  strictly inside its parent's rectangle.
- **The router needs no group-aware code.** An edge whose endpoint is the box is anchored on the group's id
  by the host, which makes it an ordinary drawn edge that terminates on the frame's border — the arrow's tip
  x IS the box's left border. `overlaps` is audited PER FRAME and the union is what the geometry serves, so
  the no-two-runs-share-a-pixel promise extends to every interior unchanged.
- **One canvas, absolute coordinates.** The nested branch emits every card, run and frame in the canvas's
  own pixels (`nodes[].left/top/width/height`, `groups[].left/top/…`) and the DOM positions the cards
  absolutely instead of inside rank columns; a box's interior is re-planned at the origin its box was
  placed at, so the painted path and the polyline a test proves containment with are one curve.
- **A flat team is untouched.** With no `groups` in the model the geometry carries no `groups` key, no
  `nested` flag and the render emits no frames layer at all, so a flat picture's bytes and DOM are what
  they were before subcells existed.
- **DECLARED BOUNDS.** A cyclic dependency INSIDE one frame is not routed by this build (the flat path
  draws it on the left); the geometry lists its witness in `nestedBackEdges` so the omission is visible
  rather than silent. Columns are packed in rank order and stacked top-aligned — no barycentre relaxation,
  unlike the flat path — and the hover halo covers the root frame's cards (an interior card keeps its own
  tone).

## The Workbench page — one `conversation.view` entry

`src/web-client.ts` registers ONE `conversation.view` entry — id `mpd-workbench`, label `Workbench`,
locale namespace `mpdWorkbench` — which the conversation shell renders as a full-page tab beside
Chat/Trajectory.

- **What it shows.** The team header (phase, id, member count) with the hold line and the two buttons
  under it, then the task board's rows (id, owner, status). The empty states are explicit and separate:
  still reading, unreadable routes, no team in this session, a STAGED plan awaiting approval, nothing
  staged, and the other teams this workspace holds.
- **It READS three existing routes.** `/plugins/mpd-team/state` and `/plugins/mpd-team/plan` (the mpd
  record) plus `/plugins/mpd-team-watchdog/state` (the live holds), re-read on its own 3000 ms interval —
  the page has no stream.
- **It WRITES only through the two fenced watchdog routes.** Pause POSTs
  `/plugins/mpd-team-watchdog/hold` with `{teamId, reason: "workbench"}`, so a human pause records its own
  cause instead of the watchdog's `silence`; Resume POSTs `{teamId}` to
  `/plugins/mpd-team-watchdog/resume`. Both buttons are disabled while a write is in flight, and the page
  re-reads the routes instead of trusting the POST's echo.
- **The registration is GATED.** The entry waits for the shell's own `conversation.view` declaration
  through `ctx.slots.inject`; a slot that never arrives, or a registry that refuses the registration,
  costs the TAB and nothing else — ONE diagnostic line names the reason and the rest of the client mounts
  as usual.
- **`order` is NOT used.** The shell projects its tab list from registration order, so the entry registers
  on the slot's first declaration instead of competing for a position.

## The DSH Go native surface (contract `.mpd/plans/dshgo-native-parity.md` D2–D5)

The root `dshGo` manifest contributes **two panels**, one composer strip, two composer actions and two
message actions; each panel has a hand-written STATIC v1 fallback under `dsh-go/views/`, and this package
publishes the LIVE half under the SAME ids, so the app upgrades a fallback in place instead of listing
two entries.

| slot | id | live half |
|---|---|---|
| `panels` | `mpd` | `registerDshGoPanel` (`src/dshgo-panel.ts`) |
| `panels` | `mpd-team` | `registerDshGoTeamPanel` (`src/dshgo-team-panel.ts`) |
| `composer.strip` | `mpd-status` | `registerDshGoSurfaces` (`src/dshgo-surfaces.ts`) |
| `composer.actions` | `mpd-dispatch` | `registerDshGoSurfaces` |
| `composer.actions` | `mpd-board` | static `open` effect in the manifest, no handler |
| `message.actions` | `mpd-save-memory`, `mpd-copy-reply` | `registerDshGoSurfaces` |

- **Registered lazily and silently.** One attempt at `apply`; a host without the `dshGo` bridge gets one
  log token (`dshGo=absent`, `dshGo=team-absent`, `dshGo=surfaces …`) and one `onServiceBound(["dshGo"], …)`
  subscription, no poll and no throw, and a host that binds the bridge later is upgraded once.
- **The view is v2 and theme-following (contract §7).** Both roots are built by the adapter's
  `panelView()`, which writes `v: 2` and `accent: "app"` in ONE place, so a named or hex accent is
  unrepresentable. Each tab carries exactly one `tinted` hero (the app's theme-tinted material), its
  metrics inside a v2 `grid`, a `surface` section with a header and a `divider`, a designed `emptyState`
  instead of a blank tab, and at most one `style: "primary"` action. Statuses are `badge`/`tone` **with a
  word**; member initials are a `badge` (`avatar` is the image node); free text sets `maxLines`. No radius,
  size, opacity, gradient, shadow or colour literal appears in a view — that is the App's to decide, and
  the kit's builders refuse one.
- **`adaptView` is the fallback.** An app below 1.0.9 (or one whose `caps.components` omits a v2 name)
  receives the SAME tree downgraded to v1: tabs become a stack of titled sections, the grid becomes a
  list, badges become text, `divider`/`spacer` disappear and every `style`/`accent` is stripped. One
  builder produces both shapes, so the fallback cannot drift; a metric's label AND value survive the
  grid→list rewrite.
- **What the workbench panel shows.** Four tabs — Overview (hero counters, completion bar, the first
  alert, the ready rows, and the actions), Questions (the FIRST parked question only, its options and a
  free-text form), Workmates (the library, read-only) and Memory (the last ≤ 10 entries and the reflection
  counters, read from the store's documented layout).
- **What the team panel shows.** Four tabs — Board (a tappable row per task; a tap carries
  `{id: "select", args: {task}}` and the Detail tab follows it), Members (initials badge + name + mode +
  handoff word), Detail (owner, status, kind, dependencies and verdict, plus a line saying settling is the
  owning member's job) and Watchdog (the predicate in force, the preserving hold and the last ≤ 5
  incidents, read through `session-watchdog-status` with the `mpdWatchdog` hold registry as the fallback).
- **What they push.** `data(scope, emit)` polls at 2000 ms (the 0.5 Hz ceiling), emits ONLY when the
  serialized model changed, and returns the cancel function that clears its interval. The workbench model
  is `{ team, plan, question, readyTasks, counts, alert, workmates, memory }` — ids, names, statuses,
  counts, the question's own text and task titles, never a filesystem path, a token or a credential.
  `view` builds from a LIVE read of the same services instead of the push cache, because the app fetches
  the view BEFORE it subscribes. `refresh` fires only when a STRUCTURAL signature changes: the parked
  question's identity (id plus its option labels — the buttons carry literal labels) or the ready-task id
  set. A text-only change travels on the data push.
- **Taps.** `approve`, `dispatch`, `refresh` (the protocol's `{refresh:true}` shorthand), `answer:<n>` and
  `answer-custom` on the workbench panel; `select`, `back` and `refresh` on the team panel. **Neither panel
  MUTATES through a tap**: a tap carries no agent, so `agent_teams_task` would refuse every owned row, and
  the watchdog tools resolve their workspace from the environment rather than from the panel's session.
  Settling a row stays with the owning member and pausing a team with the captain's tools; the Detail and
  Watchdog tabs say so instead of showing a button that cannot work. The question taps act on the identity the VIEW captured (parked id, item ids, raw
  labels), never on whatever sits in the parking lot now: a gone question answers "That question is gone"
  and asks for a refresh. Every handler answers an effect and NEVER rejects.
- **The 3-second window.** The app runs an effect only if it arrives within 3 s of the tap and gives
  handlers the same budget, so a slow service is acknowledged with the v1.1 DEFERRED shape
  (`{ pending: { label, timeoutMs }, result }`, `timeoutMs` up to the app's 60 s) and the real effect is
  delivered by `result`. The old 4-second in-handler timeout is gone.
- **The strip** is ONE line of at most 24 characters, chosen by `caps.locale` (`3 ready · 1 active` /
  `3 就绪 · 1 进行`), prefixed `❓` when a question is parked, `warn` when a plan waits for approval, and
  emitted only when it changes.
- **Declared bounds.** Slots are **local engine only** (the relay blocks `/dsh-go/*`, so a remote host
  renders tool cards); without this host half the static views are what renders, with no live values; the
  actions need a **live conversation**; settling a board row and pausing a team are NOT offered here (a tap
  carries no agent identity, so the team tools would refuse every owned row, and the watchdog tools would
  resolve a root from the environment rather than the panel's session); and the Flutter app is not in this
  workspace, so the checker plus the unit tests pin the protocol shape while the RENDERED look stays
  **unproven** (no PNG preview without Flutter).

## Config

None. This is infrastructure: the self-row carries no config in the bundle patch.

## Regenerating the client

```bash
node scripts/build-mpd-client.ts   # after editing src/web-client.ts or agent-teams client
node scripts/pack-mpd.ts           # restage the bundle
```

## Files

- `src/index.ts` — the no-op main plugin.
- `src/dshgo-panel.ts` — the workbench panel's live half: the read model, the deferred tap actions and
  the registration (`panel('mpd', …)`).
- `src/dshgo-team-panel.ts` — the team panel's live half (`panel('mpd-team', …)`): the board/member/detail
  readers, the per-scope selection store and the `select` / `back` / `refresh` actions (no mutation — an
  anonymous tap cannot own a board row or name the session's workspace root).
- `src/dshgo-views.ts` — the PURE view builders for both panels (kit builders only; no services, no I/O).
- `src/dshgo-copy.ts` — the panel copy in English and 简体中文, selected from `caps.locale`.
- `src/dshgo-surfaces.ts` — the composer strip and the three menu handlers.
- `src/web-client.ts` — the mpd client factory body (plain JS, React.createElement).
- `src/team-view.ts` — the shared TEAM view factory body both sidebar hosts render (the member cards,
  the dependency DAG and the poll-plus-push refresh described above). Spliced into the client as
  `MPD_TEAM_VIEW`; it takes the routes, the interval and the translator as dependencies.
- `src/team-page.ts` — the team-WATCHDOG sidebar page factory body (module id
  `@mpd-dsh/team-page`), built into `client.js` the same way. It requires no adopted client:
  it polls this bundle's own watchdog routes.
- `client.js` — the generated combined client (committed; it still embeds the retired
  agent-teams client artifact because the build script does, and nothing requires it).
