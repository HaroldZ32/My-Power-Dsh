## T-92 — the captain test must not key on the agent PRESET (fixed 2026-10-08)

**Symptom.** A human's own top-level session is refused `git branch` / `git commit` / `git add` with
`one-git-writer rule (AGENTS.md §5): this session is NOT the workspace's top-level captain`, even though
the session IS the top level — and the sentence asserts a fact the code never tested.

**Cause (measured).** `sessionQualifies()` in `packages/mpd-roles-plugin/src/complexity-gate.ts` decided
"captain" as `header exists && header.parentSession === undefined && presets.includes(header.agentPreset)`,
and the guard row installed `presets: ["mpd"]` (default `DEFAULT_GATE_PRESETS = ["mpd"]`). Decoding the
FIRST frame of every stored session log under `~/.dsh/sessions/**` (36 sessions) gave:
`cordis`/depth 0 = **17**, `mpd`/depth 1 = 11 (spawned team members), `cordis`/depth 1 = 5,
`standard`/depth 0 = 3. **Every top-level session on this machine records `agentPreset: "cordis"`** — the
dsh-tui launcher passes `preset: DSH_TUI_PRESET ?? undefined` and the harness then records its own default
preset id — while the only `mpd` sessions are children, which the parent test excludes. The captain branch
was therefore UNREACHABLE: no session could satisfy both tests, and the whole checkout had no legal git
writer. `AGENTS.md` §5 never mentioned a preset; the narrowing was an undocumented, stricter
implementation of the rule.

**Fix.** The captain question is now answered by the property the rule is actually about — the workspace's
top-level session (`delegationDepth` 0, no parent session) — and both the git rule and the captain's write
rule use that predicate. The session-start gate and the roster section keep their own preset coverage,
which is a different question. **The fix takes effect only after `dsh` restarts** (T-21: no plugin hot
reload), so a session already running keeps the old guard.

**Repro / evidence shape.** Decode one session header (`zlib.zstdDecompressSync` over the FIRST frame of
`<DSH_HOME>/sessions/<projectKey>/<sessionId>/session.v4.jsonl.zstd`) and compare `agentPreset` to the
guard's configured `presets` list; then attempt `git status` (allowed) versus `git branch --show-current`
(a write subcommand's sibling) from that session.
