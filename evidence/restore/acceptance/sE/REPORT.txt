Nothing under `docker/**`, `scripts/**` or `skills/**` was touched.

## What the workflow does

`workflow_dispatch` (optional `npm_registry` input) + nightly `schedule` ("41 3 * * *") → one job on
`ubuntu-24.04`, job timeout 60 min, lane step timeout 50 min:

    node scripts/docker-e2e.ts --mode source --require-docker --allow-rootful-docker --no-browser

then `actions/upload-artifact@v7` of `evidence/docker/client-install*/` under `if: always()`, then a step
that prints every stamp directory (newest first), the driver's flags, and every FAIL / NULL row with the
lane's own reason — to the log and to `$GITHUB_STEP_SUMMARY`.

## Why each flag (each traced to the driver's own code or to a measured run)

| flag | the fact behind it |
|---|---|
| `--mode source` | builds from the checkout; no pushed ref needed, so it is the CI-correct mode |
| `--allow-rootful-docker` | `decideDockerUse`: a ROOTFUL daemon is SKIPPED, and a skip EXITS 0 — without this the job is green having run no container |
| `--require-docker` | the same function turns any remaining skip (no daemon / unusable) into exit 3 and names the overrides |
| `--no-browser` | `browserEnabled = argv.includes("--require-browser") \|\| !argv.includes("--no-browser")`, and a browser-enabled run adds `ui.` to `requiredPrefixes`; `finalExit = unmeasuredRequired(...) > 0 ? 3 : exitCode`. A runner has no browser → without the flag the `ui.*` nulls are exit 3 |
| no `--live` / `--require-live` | `liveRequested` adds `live.`+`boot.llmTurn` to `requiredPrefixes` AND refuses to run without `DEEPSEEK_API_KEY`; omitting them is what makes this lane credential-free. Nulls are recorded with their reasons (`decideExit` looks only at `ok`, so nulls never fail) |

Verified against the driver, not trusted from the brief:
`evidence/docker/client-install/2026-10-09T14-53-52Z/driver.json` — a credential-free source run that
passed 106 rows with 0 failures still exited **3**, with `requiredPrefixes=["live.","boot.llmTurn","ui."]`
and 8 `ui.*` rows in `unmeasured`. `node scripts/docker-e2e.ts --self-test` → exit 0, all arms passed.

## The npm registry is OPTIONAL and DECLARED, never hard-coded

`MPD_E2E_NPM_REGISTRY: ${{ inputs.npm_registry }}` at job level, input default `""`. Empty is the healthy
default: `docker/entrypoint.sh` step 01b probes the registry's scoped endpoint and falls back to its own
mirror only when the probe does not answer, recording the transport as `obs.npmRegistry`. A dispatch can
name a registry INSTEAD (the measured mirror run: pnpm 313 s → 5 s, lane to its last step in ~15 min). A
repository-variable route was deliberately NOT added — the dispatch input is the smaller surface.

## What was NOT verified (bounds)

* **The workflow has never run.** GitHub Actions cannot be executed from here. Unproven: that
  `actions/checkout@v7` / `actions/setup-node@v7` / `actions/upload-artifact@v7` tags resolve (they match
  the majors `gates.yml` already uses; v7 for upload-artifact is corroborated externally, not queried);
  that `inputs.npm_registry` renders as `""` on a scheduled run; that `ubuntu-24.04` behaves as expected.
* **A hosted runner's Docker was not re-measured** — ROOTFUL is the brief's measured fact, and the flags
  are the driver's own contract for it.
* **What CI cannot measure by construction**: the `ui.*` (8) and `live.*`/`boot.llmTurn` (28) rows are
  nulls without a browser and a key, `qa.mcpCall` with them, and the `oneclick.*` rows (4) are null in
  `--mode source` — ~41 of 118 rows. From the measured credential-free runs, the expected CI shape is
  **0 failed, ~77 passed, ~41 null, exit 0**; the exact set is in the uploaded artifact, not in this file.
* Docker is rootless on this host, so the rootful path was exercised only through the driver's pure
  `decideDockerUse` (`--self-test`), never live.
