EVERY KEY THAT LEGITIMATELY DIFFERS, and why (kept explicit in the packer, not silently derived)
  @ast-grep/cli            packed only — root declares none; a packed artifact carries no
                           .toolchain/node_modules/.bin (this packer stages no .toolchain/), so the ast-grep
                           launcher can only resolve it through the profile's node_modules.
  @code-yeongyu/comment-checker  packed only, same reason, for the mpd-comment-checker row's detector binary.
  dsh-better-sidebar       promoted from root's devDependency + OPTIONAL peer into the packed `dependencies`
                           (its node-pty postinstall is the build script pnpm 11 refuses without an approval
                           channel, AGENTS.md §8), so the sidebar host still materializes for a packed install.
  @colbymchenry/codegraph  in BOTH, identical pin (root's declaration is what the packed set now copies).

WHAT THE PACKER NO LONGER DOES: it never re-types the set. `optionalDependencies` is a COPY of the root
declaration plus the two documented pack-only keys, and `dependencies` is the packer's own policy table.
A root-declared package can no longer be dropped from the artifact by an edit in the packer's own literal.
