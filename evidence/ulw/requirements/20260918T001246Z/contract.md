## 2. Clause 2 — `/ulw` and `/ultrawork` are user-invocable

**User-visible surface.** Typing `/ulw <objective>` or `/ultrawork <objective>` starts a ULW run for
that objective and returns a short confirmation; empty input returns usage; each name is discoverable
in the command list. A plain-text `/ulw …` gesture also works with no command surface (headless).

### 2.1 Measured seam facts (the implementation must live inside these)

- The harness command registry is `@deepseek-ai/dsh-commands` (`name = "commands"`, `ctx.commands`),
  mounted in the HOST plane at `node_modules/@deepseek-ai/dsh-base/cordis.patch.yml:286`, so the
  service is available in every profile including `mpd-headless`.
- Registration API: `ctx.commands.register({name, description, input?, recordInput?, handler}) =>
  () => void` (disposer). Handler receives `{commandId, agent, rawInput, attachments, signal}` and
  returns `CommandResult = {kind:'success', text?} | {kind:'error', text}`. A command handler runs
  "without sending the command to the model".
- **A handler that only returns `{kind:'success', text}` does NOT run the objective.** Starting a turn
  requires the agent turn seam: `agent.followup(message)` ("Queue an ordinary follow-up turn and wake
  the driver; the item becomes the sole ordinary message of its own turn"). In-tree precedent:
  `packages/mpd-agent-teams-plugin/lib/command.js:222` calls
  `invocation.agent.followup(createUserMessage({…}))`.
- `AGENTS.md` §6 (binding): no plugin row may touch a harness seam directly. `mpd-ulw-plugin` is OUR
  code (the adopted `lib/` is the documented exception), and today it imports only `registerTool` /
  `spawnAgent` through `mpd-dsh-adapter`. The adapter currently exposes **no** command seam and **no**
  turn-submission seam (`packages/mpd-dsh-adapter-plugin/src/index.ts`: `inject: []`;
  `DshCapabilities` has no `commands`/`commandsRegister`, and no `followup`/`steer`/`send`).

### 2.2 REQUIRED adapter surface (D2, extended)

`registerCommand(definition) => disposer` plus `commands` / `commandsRegister` capability flags, as
D2 states. **PLUS** a turn-submission seam, because without one clause 2 is a command that registers
and never runs: the same adapter must expose a user-turn submit (name is the implementer's choice —
semantics are `agent.followup` on the invoking agent, i.e. its own turn) and report it as its own
capability flag. `onEvent` already forwards to `ctx.on` verbatim, so the pre-step gesture needs no new
seam (capability `events` already exists).

Acceptance for the adapter: a unit test proves (a) `registerCommand` returns a working disposer,
(b) both capability flags are true under a live context and false when the service is absent,
(c) a denied/absent service degrades to a warning and never aborts the plugin tree.

## 3. Clause 3 — ULW autonomy

**User-visible surface.** A ULW run asks the user nothing: it decides everything itself, forming an
MPD team when complexity demands it, and reports done only after its own verification close-out.

The policy must appear in the **activation directive** injected into the captain's session — the same
constant for the command path and the gesture path; if the implementer ships two texts they must carry
the same five clauses and a test must assert them in both.

**Contract clarification of D4's "the engine's own directive"**: the clause must **NOT** be added to
the child round `DIRECTIVE` constant (`packages/mpd-ulw-plugin/src/index.ts:68`), which heads each
round CHILD's prompt. The session-start gate deliberately never qualifies a child session
("the session is NOT a child session" — `lib/session-start.js` module doc), so a team-autonomy clause
in a child prompt would instruct a subagent to do something the platform forbids.

**Five checkable behaviours** (each needs a test, not prose):

| ID | Behaviour | Falsifiable check |
|---|---|---|
| C3.1 | **Triage-first**: an unclear or *investigate-then-execute* objective runs a normal-MPD investigation round BEFORE gate/team/loop | the delivered directive constant contains the ordered triage clause; a unit test asserts clause order (triage before gate before team before loop before close-out) |
| C3.2 | **Same complexity gate**: the run evaluates the SAME predicate as the session-start gate — explicit `team:`/`!team` flag OR `>= 1` matched signal (A–D) — and does not invent a second predicate | the directive names the four signals and the `explicit flag OR any matched signal` rule; no second predicate literal is introduced in `packages/mpd-ulw-plugin/src/**` |
| C3.3 | **Auto-approved team when warranted**: when the gate fires (or complexity warrants), the run calls `agent_teams_create(approval="automatic", profile="mpd")`, designs the roster/DAG, and runs with no user confirmation | the directive contains `approval="automatic"` + `profile="mpd"`; the clause-4 advisory notice must not forbid automatic staging (consistency check in §4.3) |
| C3.4 | **Loop to completion without asking**: never stop early to ask; rounds continue until every criterion is clean | the directive contains the no-ask clause; `mpd_ultrawork`'s existing round loop (`for (round…)` with `allClean(criteria)`) is unchanged in that respect; `bun test` green |
| C3.5 | **Verification close-out**: the verification gate + quality-gate ledger must approve before reporting done | existing engine behaviour is preserved and asserted: `status = "blocked"` when any gate lane verdict is `FAIL`; `verdict` + `ledger` are non-empty on a completed run |
| C3.4b | **Fix on sight** (D4(f), part of C3.4): a defect found by the run is fixed in the same turn — never report-and-wait, never ask approval | the directive contains the fix-on-sight clause; the wave's own lanes obey §8 R1 |

REQUIRED: the policy is **English-only** text in source (AGENTS.md language policy), and the directive
must not promise a capability the platform lacks (e.g. it must not tell the captain to "approve
automatically" a team in *normal* mode — the scope note in plan §1 keeps auto-approval a ULW feature).
