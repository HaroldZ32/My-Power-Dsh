5. ROOT CAUSE of the oneclick abort (and the proof of it)
================================================================================
Symptom: oneclick run evidence/docker/client-install-oneclick/2026-10-02T16-36-24Z —
  fact abort = "unexpected shell failure (exit 1) near line 725"; 16 assertions passed (install,
  git spec, packed `files` allowlist, dist byte-identity) and 30 came back NULL because the lane died.

Cause (reproduced locally, not guessed): in oneclick mode the installed bundle lives UNDER
node_modules, and Node refuses to strip TypeScript there:

  $ cd <pkg>/node_modules/@mpd-dsh/mpd && node scripts/verify-no-host-override.ts --allow-no-host
  exit=1
  node:internal/modules/typescript:189
      throw new ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING(filename);
  ^
  (no verdict line on stdout)

The old code then piped the gate's output through `grep -E 'PASS:|NOTE|VIOLATION|FAIL'`, which
matched nothing; under `set -o pipefail` that made the whole assignment non-zero, and this file's
`trap 'on_error' ERR` turned it into a lane abort. Two independent defects: the gate could not run,
and the pipeline could not survive a witness that produces no verdict line.

Fix (both halves):
  * the gate's source is COPIED out of the installed tree into `$WORK_DIR/no-host-override-subject/`
    together with `package.json` + the two patch layers, and run there; `cmp` asserts the subject is a
    byte-identical copy of the INSTALLED layers (raw: `subject=byte-identical`);
  * the verdict is classified — exit 0 = witness, `FAIL:`/`VIOLATION` = REAL FINDING (arm false),
    no verdict line = UNAVAILABLE (named in the raw, the structural read still decides) — and the
    gate's own output is PRINTED into the step log instead of only grepped.
