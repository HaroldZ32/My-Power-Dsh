# Release and install audit repair

The release workflow packs the repository once, installs that tarball in fresh Web and TUI profiles, checks the tarball digest again, and passes the same path to npm staging. The ordinary push and pull-request gate performs the same two-profile smoke without a staging step. Each profile's first AST search matched one fixture declaration and returned zero matches for an absent declaration. The launchers resolved to fresh profile copies, their bytes matched the archive, and the smoke verified the archive's SHA-256 after both runs. The installed copies carried no `.toolchain`, and the process had no ambient `ast-grep` or AST path override.
