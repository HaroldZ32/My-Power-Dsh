# mpd-bundle-plugin

**English** | [中文](./README.zh-CN.md)

The `@mpd-dsh/mpd` bundle's own main plugin and web-client surface. Two jobs:

1. **Web-compat main** — the bundle package's `main` / `exports["."]` points here. It
   is a no-op plugin (`apply() {}`) whose name is `@mpd-dsh/mpd`. The bundle patch's
   `mpd-web-compat` self-row (`name: '@mpd-dsh/mpd'`) loads it, which makes the loader
   entry named **exactly** `@mpd-dsh/mpd` — the entry that client-modules requires to
   build a boot-graph client row for the bundle (without it no client surface loads).
2. **Combined web client** — `client.js` (generated by `scripts/build-mpd-client.mjs`)
   is served as the bundle's `./client` export:
   - the adopted agent-teams `lib/client.js` verbatim (registers
     `@nanmicoder/dsh-agent-teams`). It is used strictly as a **view library**: the
     additive export bridge applied by `scripts/patch-agent-teams-client.mjs` (re-applied
     by `scripts/vendor-agent-teams.mjs`) exposes its views/store/locales/CSS, and its
     `apply(ctx)` is never called — that is what registered the removed in-conversation
     team card and activity floater,
   - a `@mpd-dsh/team-page` registration whose factory is `src/team-page.js`: the
     **AgentTeams page**, contributed as a **DSH-better-sidebar** tab (id
     `mpd-agent-teams`, order 85, `single: true`, live-team-count badge, the
     `autoOpenOnTeamActivity` switch, per-conversation scope). It is the ONLY team GUI:
     without that sidebar it logs one warning and registers nothing. The page renders the
     removed floater's own interior — the adopted `panel` class (which scopes the
     `--dsw-alias-*` variables every adopted rule reads), `panelHead` with the title, busy
     dot and collapse control, the `teams` body and the adopted empty hint — and only the
     window-manager half (positioning, drag/resize, floating frame) is dropped,
   - a `@mpd-dsh/mpd` registration whose factory contributes the workmate library as its
     own **DSH-better-sidebar** tab (`mpd-workmate`, order 90, `single: true`), which
     reads and creates workmates via `GET /plugins/mpd-workmate/{list,roster,get}` +
     `POST /plugins/mpd-workmate/init`, and
     renames/deletes them via `POST /plugins/mpd-workmate/{rename,delete}` — branching on
     the reason-coded refusals (`invalid-name` / `confirm-required` / `unknown` /
     `collision` / `in-use` with the blocking team list), with an explicit two-step delete
     (confirmation → archive, or a typed-name purge) and zh/en strings. It
     also registers the null `conversation.chat.commandview` row that hides the
     `/agent-teams` command result. There is NO floating fallback for either page:
     `scripts/build-mpd-client.mjs` fails the build if any mpd client source registers
     `agent-teams-activity`, `conversation.chat.node`, `shell.overlay` or
     `sidebar.footer.action`.

**TUI counterpart.** The settings card this client registers is the browser half of the same
`mpd` settings namespace the TUI edition renders as its `/settings` section
(`packages/mpd-tui-plugin/src/settings.ts`): labels, hints and zh descriptions are mirrored
between the two front doors, a test asserts the two lists stay identical, and both state the same
bridge disclosure — a save writes `<workspace>/.mpd/mpd.jsonc` for the live session workspace(s)
and the mpd plugins act on it after a restart. The browser reaches the bridge only through the
public settings seam; the write-back itself belongs to `packages/mpd-config-plugin`. Rebuild the
combined client (`node scripts/build-mpd-client.mjs`) after touching either half.

## Config

None. This is infrastructure: the self-row carries no config in the bundle patch.

## Regenerating the client

```bash
node scripts/build-mpd-client.mjs   # after editing src/web-client.js or agent-teams client
node scripts/pack-mpd.mjs           # restage the bundle
```

## Files

- `src/index.ts` — the no-op main plugin.
- `src/web-client.js` — the mpd client factory body (plain JS, React.createElement).
- `src/team-page.js` — the AgentTeams sidebar page factory body (module id
  `@mpd-dsh/team-page`), built into `client.js` the same way.
- `client.js` — the generated combined client (committed, mirroring the vendored
  agent-teams client artifact).
