## 9. Evidence convention

- Path: `evidence/<domain>/<slug>/<stamp>/`, `<stamp>` = UTC `YYYY-MM-DDThh-mm-ss.sssZ` with colons replaced by
  dashes, optionally `-<tag>` (wave 1 mixed formats; this wave pins the ISO form for new dirs so cross-references and
  digests stay comparable). Domains: lane A `evidence/agent-teams/`, B `evidence/pack-closure/` + `evidence/gates/`,
  B2 `evidence/gates/` + `evidence/docs/`, B3 `evidence/docs/`, C `evidence/team-watchdog/`, D `evidence/dsh-qa/`,
  planning `evidence/planning/`.
- Files: `result.json` (machine-readable) + `output.log` (raw, unpiped). `result.json` minimum keys:
  `{schema, captured_at, repo_head, item_ids, commands[{name, command, exitCode, log, reading, verdict}],
  findings[], corrections[]}` plus, where applicable, the artifact stamp and the corpus digest.
- A verdict is derived per command from the exit code AND that command's own success marker — never a blanket grep for
  FAIL (measured: `verify-pack-closure --self-test` prints 20 FAIL lines by design).
- Every reading names its revision (commit / file hash); two stamps are comparable only when built by the SAME method
  (lane B's correction: an earlier `| sort`-bearing stamp is not comparable to the canonical one).
- Negative controls are evidence, not intentions: a new rule is shown RED on a seeded violation and GREEN on the clean
  tree, in the same evidence dir.
- Honest bounds are mandatory: a single run window, a single settle sample, a driver reading vs a live incident, a
  disclosure vs a live reload, or a static structural argument is reported AS such.
- Ownership: one slug per task (§5.4); no cross-writes; a foreign driver is invoked with an explicit `--out` into the
  caller's own slug.
