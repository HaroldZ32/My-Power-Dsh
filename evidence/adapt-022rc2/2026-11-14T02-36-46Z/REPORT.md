## 3. CONFIRMED DEFECT in candidate-v1 (deliverable 4) — `probes must agree`

Candidate-v1 = the current working-tree `cordis.patch.yml` (T2's, uncommitted). Its decision:

```
if (findings.length > 0) { disagreement = findings.some(g => g.generation !== first)
  if (disagreement) reason = 'the probes disagree (…)'   // generation stays 'ambiguous'
  else generation = first }
```

That makes EVERY readable probe a veto, so **stage 1 is not authoritative**. Measured with the real binaries and
real profiles (`candidate/result.json`):

| input | nearest (stage 1) | profile-local harness (stage 2) | presence (stage 3) | candidate-v1 | reference (rule) |
|---|---|---|---|---|---|
| rc.1 host + rc.1 profile | rc.1 → old | unresolved | old only | **old enabled** ✔ | old enabled |
| rc.1 host + **rc.2 profile** (mixed) | rc.1 → old | unresolved | new only | **BOTH DISABLED** ✘ | old enabled |
| rc.2 host + **rc.1 profile** (mixed) | rc.2 → new | unresolved | old only | **BOTH DISABLED** ✘ | new enabled |
| rc.1 host + profile-local rc.2 harness | rc.1 → old | rc.2 → new (inside profile) | neither | **BOTH DISABLED** ✘ | old enabled |

Verbatim candidate log line for the mixed rc.1 case:

```
[mpd-team-rows] generation guard: BOTH row sets DISABLED - the host generation is unreadable or ambiguous (the probes disagree (running harness 0.2.2-rc.1 at …/.qa-tmp/dsh-022/lib/node_modules/@deepseek-ai/dsh => old; team package presence under …/profiles/t1/node_modules: only @deepseek-ai/dsh-agent-team is present => new)); set MPD_DSH_TEAM_ROWS=old|new to override, or =off to keep this conservative path
```

**Verdict: CONFIRMED DEFECT**, exactly the one the lead ordered fixed. T2's precedence pass (stage 1 authoritative,
stage 2 only if 1 unreadable, stage 3 only if both unreadable, both/neither = NO SIGNAL) removes it; note that
candidate-v1's stage-3 `hasOld !== hasNew` test is already the correct "both/neither = no finding" form.
