# RTL IP 设计流程指南

[English](./rtl-ip-flow-guide.md)

`rtl-ip` agent-teams roster profile 封装了一整套四阶段、带门禁的 RTL IP 设计流程。
本文说明如何启动它以及每一步的产出。

## 启动流程

```
/agent-teams --profile rtl-ip <用你手头已有的任意材料描述这个 IP：一句话、文档、规格片段…>
```

队长（captain）会先向你提两个前置问题（一次问齐）：

1. **HDL 语言** — Verilog/SV（代码工程师执行 `rtl-codestyle` 风格契约）或 SpinalHDL/Chisel
   （代码工程师遵循你项目的 Scala 约定）。
2. **验证后端** — 开源链（cocotb + verilator 覆盖率）、VCS（UVM + urg/FSDB）
   或自动适配（探测可用通道）。

两个答案对整个流程生效；中途更换只能重开流程。

## 四阶段

| 阶段 | 负责角色 | 产出物 | 门禁 |
| --- | --- | --- | --- |
| 1. 需求分析 | 需求分析师 | 苏格拉底式问题清单 + 答复汇总 + 需求摘要（只读） | 用户答复全部问题 |
| 2. 规格设计 | 规格设计师 | 需求规格 + **用户手册**（按 `user-manual.md` 模板） | **门禁 1 —— 用户手册评审（暂停等待）** |
| 3. 代码设计 | RTL 代码工程师（所选语言线）+ 验证工程师（并行） | RTL 代码 + **详细设计手册**（按 `detail-design.md` 模板，与代码一一对应）+ 验证代码 + **验证计划**（按 `verification-plan.md` 模板） | **门禁 2 —— 用户+验证评审（暂停等待）**；规格差异回退 |
| 4. 设计验证 | 验证工程师 | 双轨报告（功能轨+覆盖轨）附证据 | 全部用例 PASS + 覆盖率指标达成 |

## 门禁与回退规则

- **门禁 1**：用户手册交付后团队暂停，你确认前不写任何代码。修订循环只改手册，不动代码。
- **门禁 2**：代码+详细设计手册+验证代码/计划一并交付做用户与验证评审，团队再次暂停。
- **一致性规则**：详细设计手册与代码相对用户手册**不得有任何非必要差异**。
  发现实质差异时，团队会暂存第 3 步文件、重跑第 2 步修正用户手册、确认后回来重做第 3 步
  ——绝不绕过差异打补丁。

## 双轨验证

- **轨道 1 —— 功能验证**（依据用户手册）：手册中每个功能点与每个软件配置场景都有用例，全部通过。
- **轨道 2 —— 覆盖率验证**（依据详细设计手册）：验证计划中的行/状态机/条件覆盖指标被收集并报告
  （开源链 verilator 覆盖合并/报告，VCS 链 `urg` + fsdbreport）。

## 模板包

四份文档模板随 `rtl-ip-flow` 技能交付：

- `templates/req-spec.md` —— 需求规格说明书
- `templates/user-manual.md` —— 用户手册（按你的样例格式）
- `templates/detail-design.md` —— 详细设计手册（按你的样例格式）
- `templates/verification-plan.md` —— 验证计划（功能 + 覆盖目标）

## 说明

- 面向人的交付物为中文；agent 日志与提交保持英文。
- 流程复用现有 `rtl-codestyle`（Verilog 风格契约）、`rtl-verif`（cocotb/UVM 脚手架）技能与 `mpd_verif_*` 工具。
- 已确认的用户手册是唯一事实来源；决策变更 = 重跑第 2 步，然后重做第 3 步。
